# Marco general

## ¿Qué es aprender? (definición de Mitchell, 1997)

> Se dice que un programa **aprende** de la experiencia **E** con respecto a una tarea **T** y una medida de rendimiento **P**, si su rendimiento en la tarea T, medido por P, **mejora con la experiencia E**.

Ejemplo de tu práctica (Digits): **T** = reconocer qué dígito muestra una imagen; **E** = imágenes ya etiquetadas; **P** = accuracy sobre imágenes nuevas.

## Las tareas del aprendizaje automático

| Tarea | Salida | ¿Usa etiquetas? | Ejemplos |
|:--------------|:------------------------|:----------------|:-------------------------------------|
| **Regresión** | valor continuo | Sí (supervisado) | predecir un precio; ajuste polinomial |
| **Clasificación** | una **clase** (valor nominal, discreto) | Sí (supervisado) | especie de Iris, dígito 0 a 9, tumor benigno/maligno |
| **Agrupamiento** (*clustering*) | grupos de datos | No (no supervisado) | segmentar clientes |

En **agrupamiento** el objetivo es que los datos de un mismo grupo sean muy parecidos entre sí y los de grupos distintos sean muy diferentes (se suelen representar con centroides). En **clasificación** las clases ya están definidas y se conocen en los ejemplos de entrenamiento: por eso es *aprendizaje supervisado*.

## Clasificación: definición formal

En un problema de clasificación cada instancia se representa con un **vector de atributos**

$$\mathbf{x} = [x_1, x_2, \dots, x_m]$$

y la salida pertenece a un conjunto finito de **clases**

$$y \in \{c_1, c_2, \dots, c_K\}.$$

El objetivo es aprender, a partir de ejemplos etiquetados, una función $f: X \to Y$ (el **modelo** o **clasificador**) capaz de asignar una clase a **nuevas observaciones** sin etiquetar.

**Vocabulario equivalente** (la materia usa varios nombres para lo mismo):

| Concepto | Sinónimos |
|:---------------------|:---------------------------------------------------------|
| Una fila de datos | instancia = dato = patrón = muestra = observación |
| Una columna de entrada | atributo = característica = variable predictora = *feature* |
| La salida | clase = etiqueta = *label* = variable objetivo (*target*) |
| Datos con etiqueta conocida | conjunto de entrenamiento |

## Formas de caracterizar un clasificador

Un mismo clasificador se puede describir desde varios ejes. **No son excluyentes.**

| Eje | Opción A | Opción B |
|:---------------|:--------------------------------------|:--------------------------------------|
| **Cantidad de clases** | **Binario**: dos clases (se denotan +1 y −1). La *clase positiva* es la de mayor interés en predecir bien. | **Multiclase**: más de dos clases. Algunos clasificadores nacieron binarios (SVM) y se adaptan a multiclase. |
| **Tipo de salida** | **Determinístico**: entrega directamente una etiqueta discreta. | **Probabilístico**: asigna a cada clase un valor entre 0 y 1 (la probabilidad de pertenecer a ella); los puntajes de todas las clases suman 1. |
| **Forma de la frontera de decisión** | **Lineal**: separa con un hiperplano (recta en 2D, plano en 3D). | **No lineal**: genera superficies de decisión más complejas. |
| **Objetivo del modelo** | **Predictivo**: importa clasificar bien instancias nuevas, con buena precisión y rápido. | **Descriptivo**: importa además identificar *qué características distinguen las clases* y justificar la decisión (útil en aplicaciones críticas como el diagnóstico médico). Ejemplo típico: el árbol de decisión, porque muestra las reglas. |

Un mismo modelo puede servir para predecir y para describir.

![Izquierda: las clases se separan con una recta (problema lineal). Derecha: círculos concéntricos, ningún hiperplano las separa (problema no lineal).](fig/f0_lineal.png){width=80%}

> **Clave.** *Frontera de decisión* = el conjunto de puntos del espacio donde el clasificador cambia de una clase a otra. *Lineal* significa que esa frontera es un hiperplano. LDA produce fronteras lineales; SVM es lineal pero, con un *kernel*, se vuelve no lineal; KNN produce fronteras no lineales (irregulares) por naturaleza.

# Datos, evaluación honesta y selección de modelos

Este capítulo es el que más se repite en las preguntas de interpretación, porque conecta con **sobreajuste**, **hiperparámetros** y **validación**, que aparecen en todos los algoritmos.

## Entrenamiento, validación y prueba

Para estimar el desempeño sobre observaciones **no usadas durante el ajuste**, los datos se separan en conjuntos con funciones distintas:

| Conjunto | Para qué sirve | Se usa... |
|:-----------------|:------------------------------------------------------|:--------------------------|
| **Entrenamiento** (*train*) | Ajustar el modelo (aprender los parámetros). | Muchas veces |
| **Validación** (*validation*) | **Comparar configuraciones** del modelo y **elegir hiperparámetros**. | Muchas veces |
| **Prueba** (*test*) | **Evaluación final** del procedimiento elegido. | **Una sola vez**, al final |

> **Clave.** El conjunto de prueba **no se toca** para decidir nada (ni K, ni C, ni γ, ni para desempatar). Si se mira el resultado en test y luego se cambia el modelo para mejorarlo, el test deja de ser independiente, se produce **fuga de datos** (*data leakage*) y el desempeño reportado es **optimista y falso**. Es una de las preguntas más probables.

**Detalles de implementación que aparecen en tus notebooks:**

- `train_test_split(X, y, test_size=0.30, random_state=42, stratify=y)`.
- **`stratify=y`**: *muestreo estratificado*; conserva la **proporción de las clases** en cada partición (importante con clases desbalanceadas).
- **`random_state`**: fija la semilla para que la partición sea **reproducible**.
- Para lograr **70 % / 15 % / 15 %** se usan **dos llamadas**: primero `test_size=0.30` (queda 70 % de entrenamiento y 30 % temporal) y luego se divide ese 30 % en partes iguales con `test_size=0.50` (15 % validación + 15 % prueba).
- Tras elegir los hiperparámetros con validación, se **reentrena con entrenamiento + validación unidos** y se evalúa **una sola vez** en prueba. (En Digits: 1257 + 270 = 1527 muestras, 85 % de los datos.)

## Parámetros vs hiperparámetros

- **Parámetros**: valores que el algoritmo **aprende** durante el entrenamiento (por ejemplo, el vector $\mathbf{W}$ y el sesgo $w_0$ de LDA o SVM).
- **Hiperparámetros**: valores que **no se aprenden** directamente del entrenamiento, sino que **se eligen externamente** (con validación).

| Clasificador | Hiperparámetros |
|:-------------|:-----------------------------------------------------------|
| **KNN** | $K$ (cantidad de vecinos); además la métrica de distancia (Manhattan/Euclídea) y el tipo de voto (`weights`) |
| **LDA** | **Ninguno** (según la materia) |
| **SVM** | $C$ y $\gamma$ (y la elección del *kernel*) |

## Validación cruzada (*cross-validation*) y búsqueda de hiperparámetros

Una única partición entrenamiento/validación puede dar un resultado que depende de **qué muestras quedaron en cada lado**. La **validación cruzada de $k$ particiones** (*k-fold*) repite el proceso $k$ veces: en cada repetición **una partición actúa como validación y las $k-1$ restantes como entrenamiento**.

- Con 5 particiones aparecen **5 valores de accuracy** (uno por partición).
- La **media** estima el desempeño esperado ante datos nuevos (más robusta que un único hold-out).
- La **desviación estándar** mide la **estabilidad**: baja = el modelo rinde parejo con distintos datos; alta = depende demasiado de cómo se partieron los datos. También sirve para **desempatar**: entre dos configuraciones con igual media, conviene la de menor desviación.
- El conjunto de **prueba queda afuera** de la validación cruzada.
- En clasificación, `cv=5` usa por defecto *StratifiedKFold* (cada partición conserva la proporción de clases).

**Validación cruzada y búsqueda de hiperparámetros NO son lo mismo.** La validación cruzada es un *protocolo de evaluación*; la búsqueda de hiperparámetros es *probar combinaciones* de hiperparámetros. Se combinan: se evalúa cada combinación con validación cruzada.

**`GridSearchCV`** automatiza esa combinación: genera **todas las combinaciones** del diccionario `param_grid`, evalúa cada una con validación cruzada, elige la de **mejor score medio** y, con `refit=True`, **vuelve a ajustar** el mejor modelo con todos los datos de desarrollo (train + validación).

**Hold-out vs validación cruzada.** Un único conjunto de validación chico (por ejemplo, 100 muestras) tiene **alta varianza**: el resultado y la configuración "ganadora" pueden cambiar mucho con otras 100 muestras, y el accuracy puede ser **engañosamente optimista** si el conjunto resultó "fácil". La validación cruzada da una estimación **más conservadora y realista**.

## Pipeline y fuga de datos

Un **`Pipeline`** encadena pasos (por ejemplo `StandardScaler` → clasificador) y los ajusta **juntos**. Su valor principal: **dentro de cada partición de la validación cruzada, el escalador se ajusta solo con los datos de entrenamiento de esa partición**. Si se escalara *antes* con todos los datos, la información de validación/prueba "se filtraría" al entrenamiento (fuga de datos).

```python
pipeline = Pipeline([("scaler", StandardScaler()),
                     ("knn", KNeighborsClassifier(n_neighbors=5, metric="euclidean"))])
pipeline.fit(X_train, y_train)      # ajusta escalador Y clasificador solo con train
y_pred = pipeline.predict(X_test)   # aplica el mismo escalado a test
```

Lo mismo vale para LDA como **transformación supervisada** (`Escalador → LDA → SVM`): como LDA usa las etiquetas $y$, debe ajustarse **dentro de cada fold**; ajustarlo sobre todo el dataset y luego hacer validación cruzada sobre lo transformado **filtra información**.

## Sobreajuste y subajuste

| | **Subajuste** (*underfitting*) | **Sobreajuste** (*overfitting*) |
|:-----------------|:------------------------------------|:------------------------------------------|
| Qué pasa | El modelo es **demasiado simple** para la estructura de los datos | El modelo es **demasiado complejo**: **memoriza** el entrenamiento, incluido el **ruido** |
| Error de entrenamiento | **Alto** | **Bajo** (o nulo) |
| Error de validación | **Alto** | **Alto** (mayor que el de entrenamiento) |
| Se ve como | ambas curvas altas | brecha grande entre entrenamiento (bajo) y validación (alto) |
| Qué probar | modelo más flexible | modelo más simple / más regularización / más datos |

![Al aumentar la complejidad el error de entrenamiento baja siempre, pero el de validación tiene forma de "U". Debajo, hacia dónde apunta la complejidad para cada hiperparámetro.](fig/f7_complejidad.png){width=85%}

Idea central (*compromiso sesgo–varianza*): un modelo muy simple tiene **alto sesgo** (no captura el patrón); uno muy complejo tiene **alta varianza** (se adapta al ruido y cambia mucho con otros datos). Se busca el punto intermedio con **validación**, nunca mirando solo el error de entrenamiento.

**Cómo se manifiesta en cada algoritmo** (esto es lo que más conviene tener a mano):

| Hiperparámetro | Valor que **subajusta** | Valor que **sobreajusta** |
|:--------------|:---------------------------------|:-----------------------------------------|
| **K** (KNN) | K muy grande (frontera demasiado suave; en el extremo, siempre predice la clase mayoritaria) | K muy chico (K = 1: frontera irregular, sensible al ruido) |
| **C** (SVM) | C muy chico (margen muy ancho, tolera demasiados errores) | C muy grande (margen estrecho, fuerza a clasificar bien hasta los atípicos) |
| **γ** (SVM RBF) | γ muy chico (influencia amplia, frontera casi recta) | γ muy grande (influencia muy local, "islas" alrededor de puntos) |
| Grado del polinomio (regresión, examen anterior) | grado muy bajo | grado muy alto (grado 13 en el examen) |

> **Ojo.** *Nunca elijas un hiperparámetro mirando solo el accuracy de entrenamiento*: favorece siempre al modelo más complejo (K = 1, C enorme, γ enorme) porque memoriza. Con KNN y K = 1, por ejemplo, el accuracy de entrenamiento es 100 % (cada punto es su propio vecino más cercano), y eso no dice nada sobre la generalización.

## Parsimonia ante empates

Si varias configuraciones tienen el **mismo accuracy de validación**, se necesita un **criterio de desempate que no dependa del azar** ni de la subjetividad. Criterios válidos:

1. **Principio de parsimonia** (navaja de Occam): elegir el **modelo más simple** (menor C, menor γ, menor complejidad).
2. Elegir el de **menor desviación estándar** en la validación cruzada (más estable).
3. Pasar de hold-out a **validación cruzada**, que suele romper el empate.

**Nunca** desempatar con el conjunto de prueba.

## Escalado de atributos

Cuando un algoritmo depende de **distancias** o de la **geometría del espacio**, los atributos con valores numéricamente grandes dominan a los demás. Se soluciona con **estandarización**:

$$x' = \frac{x - \mu}{\sigma}$$

(`StandardScaler`: cada atributo queda con media 0 y desviación estándar 1), siempre **dentro de un `Pipeline`**.

| Algoritmo | ¿Sensible a la escala? |
|:-----------|:--------------------------------------------------------------|
| **KNN** | **Sí**: trabaja directamente con distancias. |
| **SVM** | **Sí**: el margen y, con RBF, las distancias entre muestras dependen de la escala. |
| **LDA** | En teoría **no** (es invariante a transformaciones lineales de escala); se escala igual por **estabilidad numérica** (inversión de matrices, autovalores) y para comparar todos los modelos en las mismas condiciones. |

# Evaluación de un clasificador: matriz de confusión y métricas

No existe una métrica adecuada para todos los problemas: **la elección depende de qué errores son más importantes en la aplicación**. La herramienta básica para analizar errores es la **matriz de confusión**.

## Matriz de confusión (caso binario)

Primero hay que **definir cuál es la clase positiva** (la clase de interés). En el ejemplo de cáncer de mama: **maligno = positivo = 1**, benigno = negativo = 0.

![Convención de scikit-learn y de tu notebook: filas = realidad, columnas = predicción. Recall se lee por fila; precision se lee por columna.](fig/f8_confusion.png){width=70%}

| Sigla | Nombre | Significado |
|:-----------|:--------------------------|:-------------------------------------------------------------|
| **VP / TP** | verdadero positivo | era positivo y el modelo predijo positivo |
| **VN / TN** | verdadero negativo | era negativo y el modelo predijo negativo |
| **FP** | falso positivo | era negativo pero el modelo predijo positivo (*falsa alarma*) |
| **FN** | falso negativo | era positivo pero el modelo predijo negativo (*caso que se escapó*) |

> **Ojo con la orientación.** En tu **notebook** (y en `sklearn.metrics.confusion_matrix`) las **filas son la realidad y las columnas la predicción**. En la **diapositiva de clase** la tabla está **transpuesta**: las filas son el *clasificador* (predicción) y las columnas el *Gold Standard* (realidad): TP y FP arriba, FN y TN abajo. Es la misma información. Lo que no cambia: **la diagonal principal del notebook = aciertos** (VN y VP). Antes de leer una matriz, fijate qué es fila y qué es columna.

## Las métricas

**Accuracy** (exactitud, tasa de aciertos): proporción total de predicciones correctas.

$$\text{Accuracy} = \frac{\text{predicciones correctas}}{\text{total de instancias}} = \frac{VP + VN}{VP + VN + FP + FN}$$

Útil como medida global **cuando las clases no están muy desbalanceadas** y los distintos errores tienen **costos comparables**.

**Precision** (precisión): *de todos los casos que el modelo predijo como positivos, ¿cuántos eran realmente positivos?*

$$\text{Precision} = \frac{VP}{VP + FP}$$

Importa cuando los **falsos positivos son costosos** (ej.: marcar como spam un mail importante; acusar de fraude a un cliente honesto).

**Recall** (exhaustividad; también **sensibilidad**, *sensitivity* o TPR): *de todos los casos realmente positivos, ¿cuántos logró detectar el modelo?*

$$\text{Recall} = \frac{VP}{VP + FN}$$

Importa cuando los **falsos negativos son costosos** (ej.: diagnóstico de enfermedad: un FN es una persona enferma clasificada como sana).

**F1-score**: media armónica de precision y recall.

$$F1 = 2\cdot\frac{\text{Precision}\cdot\text{Recall}}{\text{Precision}+\text{Recall}}$$

Sirve cuando se quiere **una única medida que considere ambas a la vez**. Es baja si *cualquiera* de las dos es baja (la media armónica castiga los desequilibrios). **No significa que F1 sea siempre mejor que accuracy**: la métrica se elige según el objetivo.

*Extra, no está en las diapositivas pero puede ser útil:* **especificidad** $= VN/(VN+FP)$ (la proporción de negativos reales bien identificados); con recall/sensibilidad forma el par clásico en medicina.

## Cuándo usar cada una

| Situación | Métrica a mirar | Por qué |
|:--------------------------------------|:------------------|:-------------------------------------------------|
| Clases equilibradas, errores de costo parecido | Accuracy | resume el desempeño global |
| **Clases desbalanceadas** | Precision, recall, F1 (por clase) | el accuracy puede ser alto aunque el modelo ignore la clase minoritaria |
| Un **FN** es grave (enfermedad, falla de seguridad) | **Recall** | interesa no dejar escapar casos positivos |
| Un **FP** es grave (spam, fraude, tratamientos invasivos) | **Precision** | interesa que lo marcado como positivo lo sea de verdad |
| Importan ambos y se quiere un solo número | F1 | media armónica |

> **Trampa clásica del accuracy.** Con 95 sanos y 5 enfermos, un modelo que **siempre responde "sano"** tiene **accuracy 95 %** y **recall 0 %**: no detecta a ningún enfermo. Por eso, con desbalance, el accuracy solo **engaña**.

**Compromiso precision–recall.** Suelen moverse en sentido contrario: si el modelo se vuelve más "sensible" para no dejar pasar positivos (sube el recall), tiende a generar más falsas alarmas (baja la precision), y viceversa.

## Ejemplo trabajado: cáncer de mama (tu notebook)

Datos: 569 observaciones y 30 atributos numéricos (357 benignos, 212 malignos). Se **recodificó** la variable objetivo para que **maligno = 1 = clase positiva** (en scikit-learn viene 0 = maligno, 1 = benigno). Partición 80/20 estratificada con `random_state=42`: **114 muestras de prueba** (72 benignas y 42 malignas). Modelo: `StandardScaler` → KNN con $K=5$ y distancia euclídea.

Matriz de confusión obtenida:

| Realidad \\ Predicción | Benigno (0) | Maligno (1) |
|:------------------------|:-----------:|:-----------:|
| **Benigno (0)** | VN = 71 | FP = 1 |
| **Maligno (1)** | FN = 4 | VP = 38 |

Métricas (calculadas a partir de esa matriz):

| Métrica | Cuenta | Valor |
|:---------------|:------------------|:--------|
| Accuracy | $(38+71)/114 = 109/114$ | 0,956 |
| Precision | $38/(38+1) = 38/39$ | 0,974 |
| Recall | $38/(38+4) = 38/42$ | 0,905 |
| F1 | $2\cdot 38/(2\cdot 38 + 1 + 4) = 76/81$ | 0,938 |
| Especificidad | $71/(71+1) = 71/72$ | 0,986 |

**Interpretación.** Un **falso negativo** es un caso que **realmente es maligno pero el modelo predijo benigno**: le estaríamos diciendo a una persona que está sana cuando tiene cáncer. Es **el error más grave** del problema. Por eso la métrica más relevante es el **recall**: de 42 tumores malignos, el modelo dejó escapar 4 (≈ 9,5 %). Un accuracy de 95,6 % suena excelente, pero **esconde** ese punto débil. Para mejorarlo se podría probar otro K, otra distancia u otro clasificador **elegidos por validación cruzada optimizando el recall** (no por test).

*Dato de una corrida propia con los mismos datos y la misma partición:* **sin** `StandardScaler` el mismo KNN baja a accuracy ≈ 0,912 y recall ≈ 0,786. Los atributos de este dataset tienen escalas muy distintas (el área va de ~140 a ~2500; la suavidad, de ~0,05 a ~0,16), así que sin escalar **el área domina las distancias**.

## Matriz de confusión multiclase

Con $K$ clases la matriz es de $K \times K$: **una fila y una columna por clase**.

- **Diagonal principal** = predicciones **correctas**.
- Un valor **fuera de la diagonal** = una clase real que fue **confundida** con otra: la celda (fila $i$, columna $j$) cuenta las muestras de la clase real $i$ que se predijeron como $j$.
- La matriz permite ver **qué clases se confunden entre sí** (en Digits: ¿el 8 con el 1? ¿el 3 con el 8?).
- **Precision y recall se calculan por clase**: para la clase $j$, *precision* = (diagonal de $j$) / (suma de la **columna** $j$); *recall* = (diagonal de $j$) / (suma de la **fila** $j$).
- El accuracy global = (suma de la diagonal) / (total).
